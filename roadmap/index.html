From project input to reviewed output

The current workflow keeps deterministic checks around local model assistance and leaves acceptance decisions with the testing professional.

  1. 01

    Initialize

    Create the contained project workspace, configuration, templates, reports, and optional synthetic samples.

  2. 02

    Validate

    Check the command, workspace, request completeness, supported testing domain, and safety before provider use.

  3. 03

    Assist locally

    Send sanitized workflow input only to the configured LM Studio endpoint and validate its structured response.

  4. 04

    Review

    Inspect the generated finding, case, dataset, report, or automation starter before using it in testing work.

What the current build does not provide

These boundaries prevent the development record from implying functionality outside the implemented release candidate.

  • No browser product interface.The implemented product experience is the qae CLI.
  • No cloud-model workflow.AI-assisted commands use the configured local LM Studio provider.
  • No public package-index release.Installation uses a trusted local wheel or source checkout.
  • No autonomous QA decisions.Generated results are advisory and require professional review.
  • No universal document export.Report workflows currently produce their documented Markdown or structured command output.
