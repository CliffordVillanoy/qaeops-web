    Terms of Use

    Last updated: October 1, 2026

    Clear boundaries for evaluating QAEOps and using its testing assistance responsibly.

    Professional judgment remains essential. QAEOps assists software testing work. Review generated findings, data, reports, and automation before using them in a project or release decision.

    Scope and current status

    This page describes the usage boundaries documented for the QAEOps 0.1.0 release-candidate CLI and this informational website. It follows the current repository’s licensing statement, security policy, supported workflows, and known limitations.

    The implemented product is the qae command-line application. The website provides documentation and setup guidance. A browser product interface, cloud-provider support, and the deferred service integrations listed in the repository are outside the current release scope.

    Ownership and licensing

    The repository’s package metadata declares LicenseRef-Proprietary. Its README states that no open-source license has been selected and that all rights are reserved by the project owner.

    Public access to the repository and documentation does not itself grant an open-source license or permission to redistribute, sublicense, or use the software beyond any permission provided by the owner. This page does not grant additional software rights. Confirm the applicable permission with the owner before relying on a use or distribution right that is not stated in the repository.

    Supported and responsible use

    QAEOps is purpose-built for legitimate software quality assurance and testing: requirements analysis, test-case design, synthetic test data, bug-report review, Playwright scaffolding and review, diagnostics, and local project chat.

    • Use project files and systems you own or are authorized to access and test.
    • Follow documented commands, supported input formats, workspace boundaries, and configuration options.
    • Respect request validation, software-testing domain enforcement, and safety controls. Rejected requests must not be treated as supported workflows.
    • Use synthetic or minimized data when evaluating the tool; avoid unnecessary personal information and production credentials.

    QAEOps rejects unsupported domains and unsafe or harmful requests. The presence of a testing or research label does not make a harmful request supported.

    Generated output requires review

    Model-generated findings and recommendations are advisory. Test cases, synthetic data, SQL, severity and priority suggestions, and Playwright code require a testing professional to verify their correctness, suitability, and coverage against the project.

    QAEOps does not automatically execute generated testing artifacts. Treat generated code and exported documents as untrusted until reviewed. Apply the security controls of the tools, renderers, databases, and test environments where you use them.

    Successful validation or command completion does not establish that a product is defect-free, that testing is complete, or that an artifact is appropriate for production use.

    Your installation and local environment

    AI-assisted workflows require separately installed LM Studio and a compatible downloaded and loaded model. You manage installation sources, model selection, local provider settings, device permissions, storage, backups, and network access.

    QAEOps writes supported artifacts into the local project workspace. Review command options before making changes or selecting an overwrite operation. Uninstalling QAEOps preserves user-owned workspace files; you remain responsible for retention and deletion, including backups and synchronized copies.

    LM Studio, downloaded models, package sources, GitHub, and other external services have their own terms and behavior. QAEOps cannot guarantee their internal storage, output quality, latency, or security.

    Release limitations

    Model quality and behavior vary. Pattern-based secret, personal-data, domain, and prompt-injection detection is not exhaustive. Local-first operation does not protect against malware, administrators, privileged local attackers, or insecure workspace permissions.

    Resource limits and transport timeouts reduce abuse but do not provide a hard process-memory or real-time guarantee. Markdown rendering can vary between downstream viewers. Only documented file formats and workflows are supported.

    The repository reports internal review evidence; QAEOps has not received an independent third-party penetration test or formal certification. Consult the known limitations before choosing an evaluation environment.

    Security reporting and privacy

    Read the Privacy Policy for website behavior, local data, redaction, provider boundaries, and your choices.

    Report suspected vulnerabilities through the repository’s private vulnerability or Security Advisory channel when available. If unavailable, use an existing private maintainer channel to request a secure reporting route. Do not post secrets, customer data, exploit details, or suspected vulnerabilities publicly.

    Follow the security policy: use minimal synthetic reproductions, test only authorized environments, and stop if testing could affect another person or system. The release has no bug-bounty program or public security email address.

    Sources and updates

    These terms reflect the repository’s README and ownership statement, package license metadata, CLI workflow contract, known limitations, and security policy.

    As the repository’s implemented scope or licensing changes, this page should be revised and its update date changed. For usage or licensing questions, contact the owner through available project channels, without sharing confidential information publicly.
