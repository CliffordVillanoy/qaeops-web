    QAEOps / Privacy

    Privacy policy

    Last updated: October 1, 2026

    Understand what stays on your device, what the website loads, and where your control begins.

    QAEOps 0.1.0 release candidate

    Local-first, with clear boundaries. QAEOps processes project data locally and sends model requests to the configured, validated local LM Studio endpoint. Protecting local files and reviewing sensitive inputs remains part of your workflow.

    Scope of this policy

    This page describes the implemented QAEOps CLI and this documentation website. It follows the repository’s privacy and security documentation. Website hosting, LM Studio, downloaded models, and services you open through external links have their own practices.

    Website privacy

    This website provides product information, documentation, and setup guidance. Its current code contains no account registration, project-file upload, analytics service, or tracking-cookie implementation.

    • Theme preference: your browser stores the light or dark selection under qaeops-theme in local storage. You can remove it through your browser’s site-data settings.
    • Documentation search: the browser retrieves the site’s documentation HTML and matches your query locally. The search code does not send the query to an external search provider.
    • Fonts: the shared page header loads fonts and icons from Google Fonts. Those requests go to Google’s servers and are subject to Google’s privacy policy.
    • Hosting and links: this site is hosted on GitHub Pages. Requests to the host and visits to external links are subject to the destination service’s practices, including GitHub’s privacy statement.

    Project data stays in your workspace

    QAEOps reads user-selected project inputs for supported testing workflows. Configuration, reports, generated artifacts, local logs, and optional chat transcripts remain on your device. The project-local .qai workspace contains configuration and workflow directories; saved chat transcripts are stored under .qai/workspace/chats/.

    QAEOps itself has no telemetry, analytics service, cloud-provider integration, or automatic external reporting. Sharing a report, syncing a workspace, or backing it up through another application is a separate action governed by that application.

    LM Studio and downloaded models

    Provider-bound content is sent to the configured, validated local LM Studio endpoint. Supported AI workflows can run without internet access after QAEOps, its dependencies, LM Studio, and a suitable model are installed locally. Installation and model downloads may require network access.

    QAEOps does not automatically download models, start LM Studio, or fall back to a cloud model. LM Studio and model behavior are outside QAEOps’ direct control: QAEOps cannot guarantee their internal storage, retention, or model behavior. Review their settings and policies before processing sensitive material.

    Implemented privacy controls

    • Validation before provider work: supported commands check inputs, workspace paths, completeness, testing intent, domain, and safety.
    • Redaction: known sensitive patterns are redacted before provider calls; chat responses are also redacted before display and storage. Pattern-based redaction cannot identify every secret, business identifier, or personal-data format.
    • Local logs: operational logs use redaction and bounded local rotation. Sanitized errors avoid raw provider-body logging.
    • Optional metrics: conversation metrics are local, bounded, and content-free. They can describe routing, timing, context estimates, provider usage, validation disposition, and exit codes; they exclude prompts, file contents, responses, credentials, personal information, and transcripts.
    • Safe publication: workspace containment and atomic publication rules apply to supported reports and transcripts.

    Retention and deletion

    You control the files in your workspace. Uninstalling QAEOps preserves user workspaces; it does not delete reports, configuration, generated artifacts, or saved conversations. Retain or delete those files according to your project’s needs and organizational policy, including any copies in backups or synchronized folders.

    For project chat, qae new --no-save disables transcript saving, including the session’s /save action and automatic saving on exit. The /clear command clears the current in-memory conversation; it does not delete previously saved transcript files.

    Your choices and responsibilities

    • Use synthetic or minimized inputs instead of production credentials, customer data, or unnecessary personal information.
    • Protect workspaces with appropriate operating-system permissions and secure backups.
    • Review content before sending it to the local provider and before sharing generated artifacts.
    • Manage LM Studio, downloaded models, network access, terminal capture, and external viewers under your own security requirements.

    Local-first does not mean anonymous, completely private, or 100% secure. Malware, privileged local users, insecure permissions, terminal capture, backups, or other software can expose data. Generated artifacts remain advisory and require professional review.

    Sources and policy updates

    This policy is based on the current repository’s Privacy Boundaries, Security Model, Project Chat, and Privacy-Safe Metrics documentation, together with the website’s current source code.

    As implemented behavior changes, this page should be updated and its revision date changed. For security reporting, follow the repository’s security policy. For general questions, use the project’s available GitHub contact channels; avoid posting secrets or personal data publicly.
