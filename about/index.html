    Why we built QAEOps

    We believe testing judgment shouldn't be outsourced to a black box. QAEOps runs locally, structures the repetitive parts of QA work like analysis, test cases, and synthetic data, and leaves interpretation, execution, and final sign-off exactly where they belong: with the testing professional.

    See the documentation

    You stay in control, always

    QAEOps drafts analysis, test cases, synthetic data, and defect findings — but you decide what ships. Review each result before it becomes part of your test suite or release.

    Frequently asked questions

    Answers reflect the documented QAEOps 0.1.0 release-candidate functionality.

    What is QAEOps, and who is it for?

    QAEOps is a command-line assistant, run as qae, that helps QA engineers, SDETs, and test leads prepare testing work with a local LM Studio model. The website is documentation only and does not run workflows.

    Does QAEOps replace a testing professional?

    No. It prepares reviewable findings and artifacts, and a professional still interprets requirements, chooses coverage, and decides whether an output is suitable.

    What do I need to install and run it?

    You need Python 3.12 to 3.14, plus LM Studio with a model loaded and its local server running. Version 0.1.0 is a release candidate installed from a locally built wheel or a source checkout, not from a public package index.

    Does my data leave my machine?

    AI-assisted commands send requests to your configured LM Studio endpoint, and input is validated and sensitive values are redacted first. Initial setup, such as installing dependencies or downloading a model, may need internet access. Local-first is an architecture choice, not a security certification.

    Does Playwright assistance create finished tests?

    No. It generates starter files or an advisory report, and unresolved items are marked TODO until an engineer confirms selectors, assertions, and setup. Your existing source is not modified.
